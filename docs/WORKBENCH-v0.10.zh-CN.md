# Visage v0.10：固定参数与限定随机

## 打开与最短路径

直接用浏览器打开 `dist/visage-workbench.html`。它是完整离线页面，无需服务、账号、图像 API 或安装依赖。

1. 在「人物设定」填写外貌／族裔描述、性别呈现、肤色和脸型。支持自定义原文，不使用民族与五官的对应表。新配置默认固定这四项。
2. 调整想保留的五官数值，点该行「固定」；也可点区域标题的「固定本区」，一次保留该区域所有字段。
3. 在「随机边界」选择风格方向和一组或多组数值范围参考。选择只修改边界，不触发随机；重抽不会改掉勾选的预设。
4. 点「重抽未固定项」。如果不满意，可点「撤销重抽」。

只有参数和提示词会变化；本版本不生成图片，没有 3D 预览，不保证图像模型保留同一个人的身份。

## 三种不同含义

- **启用**：是否存在该参数、是否把它写进提示词。身体/头部模块关闭时，其已存数值仍可保留。
- **固定**：后续随机不改当前值及其存在状态；50 中性、0、100、缺省、关闭、继承都不会被当成相同状态。固定不等于只读，仍可手动修改，新的手动值就是以后保留的值。
- **范围 / 候选**：指定解锁后可以随机选择的上下限或列表，不等于固定一个值。

分组显示「固定本区」「部分固定」「已固定」三态。整区固定也保护当前未启用的字段，以及已有配置中的分类字段、旧版字段；解锁一个子项不会解锁其他字段。顶部「全部固定／全部解锁」只改固定规则，不改数值或范围。

## 随机究竟影响什么

- 头部结构：按选定的艺术范围参考，重抽预设中未固定的数值。原本缺省的预设数值可能被补入；要让缺省保持缺省，应固定该字段或整个区域。
- 没有预设范围的头部数值：显示「未设置（保留当前）」。只有为它配置数值范围后才参与随机。
- 脸型文字、轮廓分类：不会由数值参考预设自动替换。自定义 heart-shaped 等文字可以一直保留，不能据此保证生成图的解剖一致性。
- 风格方向：维持所选方向，只应用该方向现有的表演与造型规则；它不是身份或道德判断。
- 身体：默认不参与随机。勾选「同时重抽已启用的身体数值」后，才随机已经启用的 17 个身体轴中的相应项。固定项和关闭模块保留；未启用的身体轴不会自动补入。
- 发型、妆容、表情：没有候选列表时保留当前模块。选一项后点「将当前加入候选」，再选另一项继续加入；重抽只在此列表内选择。可把「继承」和「关闭」加入候选。清空候选即恢复保留当前模块。
- 成年外观年龄：当前为「指定成年年龄」并设置范围后才参与随机；范围仅支持 18–90 整岁。
- 人物设定文字：没有候选列表时一直保留；设置每行一个的文字候选、再解除固定，才会在原样候选内随机。没有后台生成的族裔、肤色或性别分类。

## 数值边界、固定冲突与关联组

在每行展开「随机范围」，填写下限和上限后点「应用」。取消、收起或尚未应用的输入不会改变配置。清除范围恢复该轴的预设范围；没有预设的轴恢复保留当前。

预设数值范围与自定义上下限取交集，原有中心值限制在交集内。没有预设的轴使用自定义上下限及其中点，身体默认使用 0–100 中心偏置分布。各范围都是人为编写的视觉创作假设，不是人体测量。

- 固定值超出自定义范围，或固定选择不在自定义候选列表时：整次重抽取消，显示原因，所有参数和种子保持不变。请调整范围／候选或解锁，不会强行把固定值改回范围。
- 固定值只是超出预设的艺术分布：仍原样保留，不会自动修正。
- 自定义范围与本次选中的预设分布没有交集：整次取消；可以只选兼容的数值预设。
- 某关联组中任一字段固定或因模块关闭而不能抽样：整个关联组跳过。界面显示跳过的组数和原因，不用「重新抽样后再覆盖固定值」伪装成有效关联。例：固定鼻梁宽度时，同组鼻翼宽度也可能保持不变。
- 重抽可能得到相同数值，不保证每项都改变；提示区区分重抽项与实际变化项。没有实际变化时不更换种子或采样记录。

## 外观与参数锁定的边界

固定发型、妆容或表情模块也保护它继承的原 profile 对应外观层，避免内部参数变了却仍显示「固定」。但发型遮挡、化妆和表情会改变五官的可见外观；固定基底鼻子或肤色不等于固定图像中的像素。固定肤色配合已选妆容时会显示提醒。

含手工 overrides 的模块若又配置了随机候选，必须先固定该模块，或手动去掉覆盖值再随机；不会静默丢弃覆盖。外观候选名称、上下限、版本与固定路径都严格校验，未知值不静默忽略。

## 撤销、重置与持久化

- 「撤销重抽」恢复最近一次重抽前的完整配置与种子；之后如果手动编辑、导入或读取配置，会清除这一步撤销，避免意外覆盖新改动。
- 「重置参数」恢复 v0.10 默认值和默认人物设定固定项；不删除已保存的本机配置。
- 本机保存、读取、JSON 导入导出都包含固定、范围、候选、身体随机开关和选定预设。
- 旧 workbench-v0.1 JSON 自动迁移到 workbench-v0.2，保留值并以未固定、身体不随机起步；再导出使用新版结构。face-v0.1 profile 仅在实际加入 v0.2 字段时升级，来源不被修改；全固定无操作不会升级。
- 无效、超过 1 MB 或包含危险属性名的导入会拒绝。异步读文件期间若发生编辑、重置或新的导入，旧读取结果不会覆盖新状态。
- localStorage 键保持兼容；浏览器保存失败时可导出 JSON。不要把人物敏感配置提交到公开代码仓库。

## 复现与开发验证

`constraints-v0.1` 与 `workbench-sampler-v0.1` 分别记录规则和新采样方法；workbench-v0.2 的 `sampling` 单独记录 seed、父 profile 哈希、原 sampler 记录哈希、目录哈希、实际 applied/changed 字段、跳过组、实际范围与最终外观解析。原 `profile.metadata.sampling` 和其他来源元数据不被改写为本次采样。

采样后再编辑数值、外观或约束，SEED 会标记「配置已编辑」，编译提示说明采样记录已成为历史；导出也标记 historical，不声称旧种子直接复现新手工配置。

同一来源配置、约束与 seed 可重现参数；只凭 seed 不能恢复已经丢失的来源配置。旧 CLI sample/iterate 行为和历史产物不变，新约束目前作用于离线工作台及其共享 Node API。

```bash
npm test
npm run build:web
npm run test:ui
```
