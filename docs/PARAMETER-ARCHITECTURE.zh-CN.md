# 人物参数与检查器规划

本规划针对 Visage 当前的成人角色提示词工作台。建议本轮先完成输入、重抽和输出范围的易用性修正，同时把界面分类与编译模块分开。后续按人物、形体、造型、动作和画面组织检查器；暂不实现服装、通用材质引擎或机器人结构。

这里的“固定”只保证参数不被随机操作改变；所有输出都是给图像模型的文字要求，不保证画面身份、颜色、形状或局部材质精确执行。当前图片仍是静态参考。

## 1 现有实现与需要守住的边界

依据 2026 年 10 月 1 日检查到的工作区源码和 v0.10、v0.11 文档：

- 工作台已有独立的 profile、appearance、body 和 constraints；不需要重新发明一套角色引擎
- 外观预设已经支持字段覆盖，发型和妆容各有明确字段白名单
- 缺省、关闭、明确的无、中性值和固定是不同状态；不能在界面合并
- 身体默认关闭，旧版全局随机默认不含身体；头部构图下身体参数保留但不输出。本轮新全局按钮明确覆盖所有标签，身体规则见第 7 节
- 当前人像编译器会固定添加人物身份、构图、真人肤质和面部保真句。因此仅关闭头部结构，仍不能得到真正隔离的发型输出
- 发型、妆容和表情会改变可见的五官轮廓，但不应回写基底五官参数

本规划是目标契约，不代表所有字段已经实现。文中的数据示例不是当前可导入的工作台 JSON。

## 2 采用小型模块登记表

使用三层概念即可：实体、模块、属性。

| 层级 | 负责什么 | 当前例子 |
| --- | --- | --- |
| 实体 | 当前编辑的对象及支持能力 | 一个成年人物；当前固定为 human |
| 模块 | 一组可独立编辑、解析与输出的描述 | 头部结构、身体、皮肤、发型、妆容、表情 |
| 属性 | 模块内含义明确的值 | 鼻梁宽度、发长、发色、唇面光泽 |

每个模块登记 id、中文名称、界面分组、可读写路径、编译函数和适用条件。继续沿用现有 profile、appearance 和 body 结构，通过登记表连接它们。不要现在迁移所有数据为任意属性袋，也不加入动态插件、节点图或任意物种解剖系统。

模块的界面位置不决定其输出身份。例如发型和表情暂时都在“外观”页，但应保持两个编译模块；外观年龄虽然影响面部观感，仍不是骨骼数值。

### 模块职责

| 类别 | 模块 | 拥有的内容 | 不应隐式影响 |
| --- | --- | --- | --- |
| 人物设定 | subject、age | 成年限定、用户输入的外貌与性别呈现、外观年龄 | 不按族裔、年龄或性别自动推导五官 |
| 基底形体 | head、body | 静态比例、骨架、软组织体量 | 不借妆容或表情改写基底 |
| 固有表面 | skin | 肤色、表面纹理等 | 不把灯光颜色写回肤色 |
| 造型 | hair、makeup | 发型几何、发色、彩妆区域、妆面效果 | 不继承无关的人物身份描述 |
| 动作状态 | expression、未来 pose | 面部动作、姿势和朝向 | 不把笑导致的眼裂变化存成静态眼形 |
| 画面呈现 | presentation | 构图、相机、光线、背景、展示载体 | 不直接改写人物和造型参数 |

“头部”是身体部位，“外观”是描述层，“身体”又是部位。现有三个标签可以继续使用一版，但不适合作为长期数据分类。

## 3 检查器逐步分组

本轮保持已熟悉的卡片工作台和三个标签，只调整控件行为、命名和层级。输出选择、语言和白模展示放在提示词区域；全局重抽及本页重抽清楚标明作用范围。

模块增多后，改为以下五组。先用分组列表与折叠面板，无需立即改成复杂树形编辑器。

| 分组 | 首层显示 | 展开后显示 |
| --- | --- | --- |
| 人物 | 外貌描述、性别呈现、外观年龄 | 自定义文字、候选列表和固定 |
| 形体 | 头部、身体、皮肤 | 五官区域、局部体量、表面参数 |
| 造型 | 发型、妆容 | 预设、常用覆盖、更多细节；未来加入服装和配饰 |
| 动作 | 表情 | 未来加入姿势和局部朝向 |
| 画面 | 构图、展示方式 | 相机、灯光、背景等独立设置 |

一个模块首屏只显示启用状态、当前预设、三至五个常用属性和固定状态。随机范围、候选池、遮挡提示与高级覆盖在下一层展开。正在修改的项目可以显示“预设名 · 已自定义”；不要新增一个没有来源关系的“自定义预设”并静默丢掉原预设。

下拉菜单提供常见值和“自定义”。显示名称可以中文化，保存值使用稳定 id。用户输入的原文仍保留；不要把自由文本伪装成已经验证的结构化分类。

## 4 发型等模块的属性组织

同一模块可以同时拥有形状、颜色、材料和表面属性。它们无需拆成彼此竞争的顶层标签，也不应复制到多个模块。

| 属性层 | 发型例子 | 未来服装或配饰例子 |
| --- | --- | --- |
| 形状与组织 | 长度、剪裁、刘海、分缝、卷曲、体积、编扎 | 版型、长度、层叠、佩戴位置 |
| 颜色 | 基色、局部染色 | 主色、辅色、图案颜色 |
| 材料 | 自然头发、假发或发片的已知材料 | 棉、皮革、金属等 |
| 表面表现 | 自然光泽、哑光、湿发造型 | 磨砂、抛光、拉丝、旧化 |
| 附加与遮挡 | 发饰、覆盖额头或耳朵 | 饰件、遮挡身体区域 |

当前只扩展已有发型和妆容字段的编辑体验；新增材料轴前，先确认是否真的能改变可表达的结果。

### 避免重复或矛盾

- 材料描述“是什么”；光泽描述“表面如何反光”；灯光描述“如何照明”，分别只有一个归属
- 不把已有 texture 同时用于“卷曲程度”“发丝粗细”和“表面光泽”。先保留旧字段兼容，后续再作显式迁移
- 若已有 finish 枚举，暂不再加入一个独立的 0–100 gloss 滑杆；两者都控制同一效果时会互相争夺
- 材料预设可以提供默认表面值，用户覆盖优先；不能同时输出“完全哑光”和“镜面高光”
- “湿发”可能同时包含成束、贴伏和高光，应作为组合预设解析，不是假设只有一个光泽值
- 白模属于展示覆盖，不把角色的皮肤、发色或衣料永久改成白色

服装和独立配饰留在后续阶段。当前发型预设自带的发饰可以继续作为发型的一部分；未来迁移时要明确同一饰件由谁拥有，避免重复输出。

## 5 值与约束的共同规则

优先级建议为：旧配置继承值 → 所选预设值 → 明确的字段覆盖。关闭模块会抑制该模块的内容，不等于“没有头发”或“明确素颜”；明确的无应使用对应语义值。

| 控件 | 改变什么 | 不改变什么 |
| --- | --- | --- |
| 启用或关闭 | 模块或参数是否参与内容解析 | 不等同于固定，不自动随机 |
| 固定 | 是否允许随机改当前值及其存在状态 | 不阻止手动编辑 |
| 范围或候选 | 下一次随机的合法取值 | 不立即改当前值 |
| 预设 | 提供一组有来源的默认值 | 不删除其他模块；覆盖处理必须明确 |
| 输出勾选 | 本次提示词包含什么 | 不删除参数、不解除固定、不启用身体 |
| 白模展示 | 未选内容的展示载体 | 不改已选模块属性或保存值 |

保留现有严格校验：非法字段、数值越界和未知预设直接报错。固定值与自定义范围冲突时整次重抽取消；不要自动解锁、扩大范围或修补其他字段。已有关联组按整体处理，不能只抽一半后声称相关性仍然成立。

自由文本覆盖可能产生语义冲突，暂时提示人工复查。只有已有结构化证据时才阻止组合；不要把一个未经验证的通用“兼容性引擎”引入本轮。

## 6 输出模块与上下文必须分开

输出先解析模块，再按白名单拼接。禁止先生成完整人像提示词，再用正则删除几句。模块建议至少区分 head、hair、makeup、expression、age、body；subject 与 skin 长期独立，本轮可由一个清楚标明的头部组合选项管理。

输出结果最好同时保留模块清单和内容来源，让界面能够说明“已选 1 项，附加随机上下文 2 项”。切换编辑标签，不改变输出选择。

### 本轮三种快捷选择

界面可以提供“其余部分：默认 / 随机 / 白模展示”。内部把内容补全与展示材质分成两轴，避免将来无法组合。

| 快捷选择 | 未选内容 | 已选内容 | 需要特别说明 |
| --- | --- | --- | --- |
| 默认 | 不加入未选参数，留给模型决定 | 精确按当前模块编译 | 默认不等于把隐藏参数或 50 中性值写入 |
| 随机 | 仅加入本版明确支持的、可复现的随机上下文 | 保持当前已选参数 | 属于补充输出，不能标为“仅选定模块” |
| 白模展示 | 使用没有个性化属性的白色中性展示载体 | 保留选中的形状、颜色和表面要求 | 白模仅作用于其余部分，不是整个人物变白 |

**发型例子：**仅选发型时，正常输出发长、剪裁、刘海、颜色等。白模展示再补一句“在中性、未上色的白模头上展示”，不带入保存的脸型、五官数值、外貌、性别、年龄、肤色或真人皮肤纹理。

发型自身的“脸侧层次”“齐颊长度”“露额头”仍然合法；这些是定位词，不能因为含有脸或额头就删除。隔离的是未选模块的属性，不是整个身体词汇表。

选中妆容时，白模载体不应把所选妆色也抹掉。选中年龄或皮肤时，若白模载体使目标难以表达，显示兼容提示，不暗改参数。所有模块都已选中时，白模上下文可能没有实际效果，应如实显示。

身体继续遵守现有启用和构图规则：关闭身体或选择头肩构图时不输出体型。仅勾选 body 不自动启用身体，也不偷偷改变构图；界面说明为何当前没有身体段落。

### 数据示意

以下仅表达职责，具体字段名可由实现确定，不要求本轮立即迁移现有结构。

```json
{
  "entity": { "kind": "human" },
  "output": {
    "selectedModules": ["hair"],
    "language": "zh-CN",
    "context": {
      "completion": "unspecified",
      "presentation": "white_clay",
      "presentationScope": "unselected_context"
    }
  },
  "appearance": {
    "version": "appearance-v0.1",
    "hair": {
      "state": "selected",
      "preset": "blunt_bob",
      "overrides": { "color": "dark brown" }
    }
  }
}
```

当前只支持 human；不要显示不能用的机器人、机甲或怪物选项。将来新增实体类型时，复用模块登记和界面机制，但用独立模块描述关节、装甲或非人类结构，不挤进人脸的鼻宽、肌量字段。

## 7 随机必须由明确操作触发

- 新全局按钮明确显示“全部标签”作用域，包含已启用且未固定的身体轴，并遵守固定、范围和候选。身体关闭或某轴未启用时仍保留原状
- 身体页的“重抽本页”本身就是明确选择身体作用域，可重抽已启用且未固定的身体轴，不修改全局 includeBody。身体关闭时仍不抽样，不补开未启用的轴
- 旧 API 未指定作用域时继续遵守 includeBody，以保持旧配置和调用行为；新界面不要让这个旧开关与“全部标签”按钮产生歧义
- 头部页和外观页只改本页登记路径；不以输出勾选决定重抽范围。若关联组跨出范围，整组跳过并说明
- 没有候选的外观模块保留当前值；含手工覆盖时保留现有保护，不能因为随机选到另一预设而静默丢掉覆盖
- 随机上下文使用独立种子与明确模块白名单，优先复用现有采样能力。没有定义采样能力的模块不假装随机成功
- 随机结果必须固定：可以保存已解析结果，或使用带版本、目录摘要和种子的纯函数重建。刷新、渲染、切语言、切标签及勾选输出不产生新抽样
- 每次明确重抽才更新随机记录，并保留撤销。相同输入、规则、目录版本与种子应重现相同结果
- 输出偏好与参数抽样记录分别记录。仅切换语言或输出范围不应把人物参数误标成已经重新抽样

## 8 分阶段交付

### 本轮完成

预设加自定义输入、中文界面与中文输出、自动消失的成功提示、错误保留、全局和本页重抽、选定模块输出、作用域明确的默认及白模上下文。随机上下文只覆盖已声明支持的模块，并给出可复现记录。现有保存、导入、固定和撤销继续工作。

### 下一轮整理

引入小型模块登记表；逐步将 subject、skin、expression、age 从现有标签中解耦；发型与妆容加入常用覆盖面板。仅在模块数量增长后升级五组导航。为已有字段建立中英词句和单一来源描述，保持数值分档含义不变。

### 有具体需求时再做

服装、独立配饰、姿势、结构化材料与有限组合规则。机器人、机甲和怪物在获得具体对象与验证样例后，使用新的实体配置与模块集合。

## 9 验收清单

1. 仅选发型，预先在 subject、skin、head 中写入独特标记；提示词不得带出这些标记或面部优先结尾，但保留合法的发型定位词
2. 白模展示保留选中的发色和发型；未选人物特征消失；提示词不同时要求未选载体有真人肤质和白模表面
3. 切换标签、输出模块或语言后，所有人物参数、锁和已解析随机值保持不变
4. 无输出模块时明确提示选择模块，不悄悄回退到完整人物；不复制上次仍留在屏幕上的过期提示词
5. 全固定重抽为无操作；固定缺省不被补成 50；范围冲突原子失败
6. 新全局重抽覆盖三页中的可抽样项，含已启用身体轴；本页操作不改页外数据；身体关闭或头肩构图不输出体型
7. 自定义覆盖有来源标记，改预设时不静默丢失；无采样候选的模块不随机
8. 保存、版本快照和导出恢复后，输出选择、语言、上下文及随机复现信息一致；旧配置继续可迁移
9. 中英文输出表达相同模块和分档；中文输出不把英文内部键名当成用户文案。自由文本保持原意，不能保证自动翻译的内容明确说明
10. 静态参考始终标示来源和非实时结果，不暗示参数改变已经生成新图

- `web/index.html`、`web/app.mjs`、`src/workbench/controls.mjs`：当前检查器分类与交互
